# ExamCard 1.2.0 RC 预发布候选：数据模型、兼容与回滚

状态：**1.2.0 RC PRE-RELEASE CANDIDATE CHANNEL / RC 预发布候选渠道**；应用版本 1.2.0，目标候选标识 rc.1，不是 Stable。本文件描述 RC 候选的数据边界；具体发行可用性以 [GitHub Releases 列表](https://github.com/GaryZhang12/ExamCard/releases) 为准，不代表 Stable 或特定资产已发布。

## 1. 数据库与路径

| 项目 | 1.2.0 本地候选 |
| --- | --- |
| 数据库 | IndexedDB `gd_exam_v2` |
| 用户数据目录 | `%APPDATA%\gd-exam-card-v3\` |
| v5 | 22 个对象存储 |
| v6 | 28 个对象存储 |
| 1.2.0 新对象存储 | **无** |
| 1.2.0 数据库版本提升 | **无** |
| v5 → v6 | 保持既有“用户主动完整备份 + 明确确认”的独立题库启用门 |

1.2.0 沿用原有数据库名、用户目录和 v5/22、v6/28 结构；没有新增表，没有把 v5 强制升级到 v6。v5 的 22 表历史与 v6 的 28 表结构各自保持既有兼容规则。

## 2. 结构化记录

- 学习计划：`examcard.daily-plan/v1`；严格字段、日期、优先级、`learning_mode + stages`，不使用不存在的 `phase`。
- 学习记录：`examcard.study-log/v2`；支持 `revision/revisions`、更正前后审计、软删除、外部 `source + externalId` 身份、未知正确数/时间保持 `null`。
- 复盘交换：`examcard.review-exchange/v1`；Schema `schemas/review-exchange-v1.schema.json`，合法字段示例 `templates/review-exchange-v1.template.json`。
- 复盘上下文导出：包装 `examcard.review-exchange-context+template/v1`；其中 `context.schema` 为 `examcard.review-exchange-context/v1`，`targetCatalog[]` 是 `{label, target}`，严格 `reviews[].target` 只能使用其中的 `target`，`label` 仅展示。
- 应用导出的复盘模板使用真实 `targetCatalog[].target` 与真实 `expected_hash`。源码静态模板中的全零 hash 只是字段示例，不可直接提交。

## 3. 复盘交换的实际 meta 范围

WP10 只使用精确 `reviewExchange*` 前缀：

- `reviewExchangeIndex`
- `reviewExchangeFingerprint:<semanticFingerprint>`
- `reviewExchangeBatch:<batchId>`
- `reviewExchangeEntity:<entityId>`
- `reviewExchangeRef:<targetIdentityHash>:<batchId>`
- `targetIdentityHash` 是 `type + namespace + id` 稳定身份 hash；ref value 中的 `targetHash` 是目标内容 hash，两者不可混用。
- 运行中的 opaque preview token 只在当前进程内存 Map，不写入用户 JSON。

复盘导入不会 `getAll(meta)`，不会读取或导出 `reviewReport:*` 私人 PDF Blob。批次 payload 只保存纯 JSON 规范化内容、hash、target/review/correction 证据和审计；不复制 PDF/Blob。

原始 `attempts`、`gradingRecords`、`bankAttempts`、`essayReviews` 是只读目标；结构化复盘不会覆盖原始成绩、批改或申论评分。修正只允许学习记录的业务字段，经 `StudyLog` 校验并追加 audit；身份键、revision/audit 字段不可经 corrections 修改。

## 4. 备份与恢复

- 升级/试用前：在“数据 → 备份与恢复”导出当前完整 JSON 备份，妥善保存并核对文件。
- 需要系统级回滚时：退出应用后，再离线复制整个 `%APPDATA%\gd-exam-card-v3\` 用户数据目录；不要在应用运行时复制正在使用的 IndexedDB。
- 恢复：恢复会覆盖当前应用数据；恢复前先导出当前完整备份。15 表/缺表/损坏备份按程序门禁拒绝，不能当作完整 28 表备份。
- v5 完整 22 表备份与 v6 完整 28 表备份按现有明确门禁处理；不完整或未知表备份拒绝。
- 回退到 1.1：必须使用升级/试用前的备份，并退出应用后按离线流程恢复。**1.2 新 meta 与 StudyLog v2 字段不保证可被 1.1 UI 无损编辑；不能把任意 1.2 数据目录静默降级给 1.1。**
- 1.1 → 1.2 没有 schema 版本提升，但这不等于 1.2 的新业务字段/复盘 meta 对旧 UI 无损可读写。

## 5. 安全与不变项

- 不改 `gd_exam_v2`、v5/22、v6/28、原 userData 路径、1.2.0 版本号、daily-plan 协议、Apache-2.0。
- 不新增 store，不通过 `restoreBackup` 做复盘追加导入。
- 本轮未访问真实用户 Profile；应用仍按原路径本地存储，不会因此变成无本地数据的产品。未上传私人材料、未访问粉笔账号、未自动打开 `source.ref`。
- 结构化复盘是建议性记录，不自动修改原始 Attempt、错因统计或已确认评分；UI 明确“未确认”。
- 用户未主动保存的上下文/模板不会自动外发。

## 6. 已知边界

- 无标准答案/未知正确数不猜 0 或错误；活动总时长不生成逐题用时。
- 申论首次 7/10 与复评 9/10 独立保留，不折算为客观题正确数/分母。
- 已撤销 batch 的历史 review_id 保留为历史；重新复盘必须显式使用新的 review_id 创建新实体，不支持“旧 review_id 随意复活”。
- 活动显式新批次 reimport 与 review_id 新建是两套策略，不能互相替代。
- 本轮未访问真实用户 Profile，也没有替用户执行真实备份；应用仍按原路径本地存储，上述备份/回滚步骤由用户在本机完成。
- 本指南不预编最终数字；完整自动回归与产物结果以随包 `FINAL_ACCEPTANCE.md`、`MANIFEST` 和 `SHA256SUMS` 为准。
- 真实 125%/150% DPI、标准用户安装/卸载、原生 OS 保存对话框取消仍为未运行范围，不冒充 PASS。
