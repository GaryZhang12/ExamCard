# 1.0.1 regression tests

Installed upgrade acceptance: `node tests/installed-upgrade.cjs seed` requires `EXAMCARD_PACKAGED=1` and `EXAMCARD_ELECTRON` pointing to the actual installed 1.0.0. The command creates a new safe temporary profile and snapshot. After an attended Setup upgrade, run `verify` against the installed 1.0.1. After uninstall, run `after-uninstall` against the unpacked candidate; after restoring the original installation, run `verify100` against installed 1.0.0. It checks all 21 non-meta stores by deep equality, including unchanged empty stores; it does not claim 21 categories of populated data. Installation, UAC and uninstallation require separate observed/human steps and system-state checks. This is not part of the unattended unified command. See reports/release-integration/WINDOWS_INSTALL_ACCEPTANCE.md for the unresolved ordinary-launch uninstall path.

Release integration supplement (2026-10-28): the unified command now runs 38 unit tests, including four tests preserving the public bilingual README and release status. The essay long-content fixture uses the actual `title`, `number`, and `type` fields. This is a test correction, not a production UI change.

`node tests/native-dialog-exports.cjs` is a separate attended Windows acceptance step. It opens a genuine Save dialog in an isolated profile; a human or observed native Computer Use must click Cancel within 180 seconds. It then checks unchanged store counts and actual synthetic learning-record/diagnosis export files. Do not run it unattended as part of the unified command. This run passed all three checks. Standard-user installation and real 125%/150% scaling remain untested.

Run `node scripts/test.cjs` (or `pnpm test`) from the repository root.

Unit tests need only Node.js. Electron tests require Electron 43.3.0 and Playwright 1.62.1. After the normal application dependencies are installed, install test-only tools separately, for example `npm install --prefix .test-runtime/deps playwright@1.62.1 pngjs@7.0.0 pixelmatch@7.1.0`. Set `EXAMCARD_TEST_MODULES` to the resulting absolute `node_modules` path. Set `EXAMCARD_ELECTRON` to an absolute Electron executable if the normal `electron` dependency is unavailable.

Every launch creates a new `examcard-work-test-*` temporary profile, verifies the effective userData path, and rejects `--no-sandbox`. It never uses the default application profile. Test profiles are retained for diagnosis. Never point tests at real user data. `EXAMCARD_APP_ROOT` optionally selects a separate baseline source tree; omit it for current-source verification.

Reports are written to `reports/`. A suite failure gives a nonzero exit code. The 20-question fixture is an original authored synthetic PDF, with expected stems/options taken independently from its authoring source. It is not a commercial textbook or official exam paper. Golden PDF tests compare all 80 option values and normalized stem prefixes (the production preview is truncated).

The UI matrix requests outer window sizes 960×720, 1366×768, 1920×1080, and 2560×1440; reports include actual content sizes and native display scale. These are not claims of real 125% or 150% Windows DPI verification. Off-screen portions of oversized windows are renderer captures, not full physical-monitor acceptance.

Screenshots in `reports/ui-current` are review candidates only. No baseline is automatically accepted or overwritten. To enable pixel comparisons, a human must place reviewed PNGs under `tests/visual-baselines/` and write `approved.json` with `approvedBy`, `environment.displays` matching the report, and `images` entries (`name`, `file`, `sha256`). The runner checks hashes and compares with pixel threshold .15 / changed-pixel ratio .005. Without this manifest, visual comparison is explicitly SKIPPED.

Final-stage additions: `final-electron.cjs` runs the actual bundled Chinese OCR models against synthetic raster-only pages, tests editing/graph rejection/persistence, cancellation of distinct queued files, leaving/reentering, and real isolated clearing. OCR content mismatches are recorded under `differences`; a pipeline PASS does not mean the scanned golden content matched exactly. `workflows-electron.cjs` tests import acknowledgements, objective/essay sessions, autosave, application restart, native save failure, Tab focus, and restore rollback.

Set `EXAMCARD_SIX_TASK_PLAN` to the authorized local six-task JSON for its real-input test; otherwise it is SKIP. The input is not copied into the repository. Set `EXAMCARD_LEGACY_ROOT` to verified public 1.0.0 source to create a fresh synthetic old-version profile and test upgrade/backup restoration; otherwise that suite is SKIP. The source commit used in this run was b17cabbd6102607c83f19baeb903f4c8a2983308.

After regression tests pass, run `node scripts/build-candidate.cjs` on Windows. For offline builds, set `EXAMCARD_ELECTRON_DIST` to the installed Electron 43.3.0 distribution directory. The script never publishes, sets generated EXEs to Medium Integrity, and checks production payload hashes. `node tests/portable-smoke.cjs` validates the actual portable wrapper in a new profile via its optional local CDP port. To test packaged content with the normal suites, set `EXAMCARD_ELECTRON` to `dist/win-unpacked/ExamCard.exe` and `EXAMCARD_PACKAGED=1`.

Still required separately: original DSH 25-test script (not present in the handed-over repository), independently annotated real textbook/scan samples, packaged installer acceptance with a separate standard Windows account, true 125%/150% display scaling, and human review of screenshot candidates. The automation covers selected high-risk states, not every combination of every module. Synthetic raster OCR still has recorded character errors requiring review.
